# VActives Website — Design System & Motion Direction

> **Document type:** Visual design system, interaction system, and motion specification  
> **Project:** VActives Website  
> **Purpose:** Define the visual language, layout rules, typography, color usage, component styling, interaction patterns, animation principles, responsive behavior, and design-quality standards for the VActives website.
>
> **Important:** The official project brief requires the website to feel modern, clean, energetic, professional, spacious, responsive, and accessible. It also asks the design to avoid clutter and excessive animation. This design system interprets those requirements through a more distinctive, premium, editorial, and motion-rich visual direction without turning the website into a generic AI-generated template.

---

# 1. Design Vision

The VActives website should feel:

- Modern
- Premium
- Energetic
- International
- Professional
- Human
- Confident
- Distinctive
- Motion-rich
- Editorial rather than template-driven

The visual direction should avoid looking like:

- A generic SaaS landing page
- A copied Framer template
- A typical AI-generated website
- A corporate recruitment website with stock photos and blue cards
- A page where every section is just a heading, paragraph, and three rounded cards

The design language should combine:

**Modern Recruitment + Editorial Layout + Kinetic Motion + Strong Brand Identity**

---

# 2. Core Design Principle

The most important principle is:

> **Do not design by repeating components. Design each content type according to its purpose.**

This means:

- Industries should not automatically become generic cards.
- Roles should not automatically become generic cards.
- Pricing should not automatically become SaaS pricing cards.
- Testimonials should not automatically become three equal cards.
- FAQ should not look like a default component library accordion.

Each section should receive a visual treatment appropriate to its content.

Example:

| Content Type | Preferred Treatment |
|---|---|
| Industries | Interactive panels / editorial tiles |
| Roles | Expandable editorial rows or dynamic grid |
| Recruitment Process | Scroll-linked timeline |
| Benefits | Mixed editorial layout |
| Pricing | Large typographic comparison |
| Testimonials | Stacked or draggable cards |
| FAQ | Minimal numbered accordion |
| Hiring Form | Progressive editorial form layout |

---

# 3. Anti-AI-Template Rules

The following patterns should be avoided unless there is a strong reason to use them:

- Purple-blue gradients as the default hero style
- Glassmorphism everywhere
- Bento grids used only because they are trendy
- Excessively rounded cards in every section
- Repetitive icon + title + paragraph blocks
- Decorative blobs without meaning
- Fake 3D abstract shapes that do not support the brand
- Generic startup illustrations
- Random neon glow effects
- Excessive gradient text
- Huge empty areas with no visual purpose
- Overuse of blur
- Floating cards that look generated by an AI template

The design should feel intentionally art-directed.

---

# 4. Visual Direction Name

## Active Editorial Recruitment

This direction combines:

- Editorial composition
- Large typography
- Controlled asymmetry
- Strong whitespace
- Brand-led color blocking
- Purposeful visual rhythm
- Refined motion
- Interactive micro-details

The result should feel closer to a modern creative agency or premium recruitment brand than a standard corporate template.

# 12. Typography Rules

- Hero headlines should feel visually dominant.
- Do not center-align all headings.
- Use line breaks intentionally.
- Avoid excessive all-caps.
- Use uppercase for labels, small metadata, or section numbers only.
- Body width should generally remain between 45–75 characters per line.
- Large editorial sections can use oversized phrases as graphic elements.

---

# 14. Controlled Asymmetry

The design should not force every section into perfect symmetry.

Use asymmetry when it improves hierarchy.

Examples:

- Large heading on left with small text block lower-right
- One oversized visual balanced by smaller supporting content
- Off-grid typography
- Staggered role rows
- Unequal text and image proportions

However, asymmetry must remain controlled.

Avoid:

- Random box sizes
- Awkward empty spaces
- Visually unbalanced composition

# 16. Border Radius System

Avoid making every element highly rounded.

Suggested radius tokens:

```text
xs:  6px
sm:  10px
md:  16px
lg:  24px
xl:  32px

```

Usage:

- Buttons: pill or moderate radius
- Forms: 10–16px
- Cards: 16–24px when appropriate
- Editorial rows: minimal or no radius
- Large image frames: 20–32px

The variation creates a more mature visual system.

# 17. Borders

Prefer subtle borders over heavy shadows.

Light mode:

```css
border: 1px solid rgba(22, 25, 24, 0.12);
```

Dark mode:

```css
border: 1px solid rgba(255, 255, 255, 0.14);
```

Use borders to structure information without making the interface feel boxed in.

---

# 18. Shadow System

Shadows should be subtle and contextual.

Avoid the common AI-template card shadow.

Use shadows mainly for:

- Floating navigation
- Elevated modals
- Important interactive panels
- Temporary hover elevation

Not every card needs a shadow.

# 21. Motion Philosophy

The site should feel alive and premium.

However:

> **Motion should reveal hierarchy, support storytelling, and create delight — not distract from the content.**

The user requested a website rich in animation, hovering, and modern interaction patterns.

The implementation should therefore use many small controlled interactions instead of a few extremely heavy effects.

---

# 22. Motion Levels

The animation system is divided into five levels.

## Level 1 — Global Page Motion

Used for:

- Route transitions
- Page entry
- Section transitions

Possible effects:

- Brand-colored wipe
- Mask reveal
- Text shift
- Soft crossfade

Recommended duration:

```text
450–700ms
```

---

## Level 2 — Scroll Reveal

Avoid using the same fade-up effect on every element.

Use different reveal styles:

### Headlines

- Word-by-word reveal
- Line-by-line reveal
- Clip-mask reveal

### Paragraphs

- Soft clip reveal
- Staggered lines

### Images

- Image mask reveal
- Scale from 1.04 → 1

### Dividers

- Grow from 0% → 100%

### Cards / Panels

- Staggered reveal
- Slight perspective
- Controlled translate

---

## Level 3 — Hover Interactions

Hover should be one of the strongest parts of the experience.

Use:

- Directional arrows
- Background shifts
- Text swaps
- Border motion
- Icon movement
- Subtle scale
- Subtle perspective
- Image parallax

Avoid simply adding a box-shadow on hover.

---

## Level 4 — Cursor-Based Motion

Desktop only.

Use subtly for:

- Magnetic buttons
- Interactive hero elements
- Small 3D card tilt
- Decorative visual response

Keep movement small, generally within approximately 3–10px.

The cursor should not become difficult to control.

---

## Level 5 — Scroll-Linked Storytelling

Use for one or two major sections only.

Best candidate:

**How It Works**

Possible implementation:

- Pinned desktop section
- Step number changes with scroll
- Progress line fills
- Content transitions between steps
- Visual indicator moves

Mobile should use a simpler vertical timeline.

### GSAP

- Complex sequences

- Pinned timelines
- High-control motion

### GSAP ScrollTrigger

Use for:

### CSS Transitions

Use for:

- FAQ icon rotation

### Lenis — Optional

Lenis may be used for smooth scrolling if testing shows that it improves the experience.

It should not be added automatically just because it is trendy.

---

# 24. Animation Performance Rules

Prefer animating:

- `transform`
- `opacity`

Use carefully:

- `clip-path`

Avoid continuous animation of:

- `width`
- `height`
- `top`
- `left`
- heavy `filter`
- large blur values

Animation must remain smooth on mobile and common laptops.

---

# 25. Reduced Motion

Respect:

```css
@media (prefers-reduced-motion: reduce)
```

When reduced motion is enabled:

- Disable parallax.
- Disable large scroll transforms.
- Disable magnetic behavior.
- Reduce page-transition complexity.
- Remove unnecessary continuous animations.
- Preserve usability and content hierarchy.

# 48. Microinteraction Library

The website should use many small interactions consistently.

Possible microinteractions:

- Link underline grows on hover.
- Arrow travels 4–8px.
- Icon rotates 2–4 degrees.
- FAQ plus morphs.
- Cards gain slight tilt.
- Button text swaps vertically.
- Section number animates.
- Progress line fills.
- Navbar indicator moves.
- Form labels animate.
- Success checkmark draws.
- Role rows expand.
- Images shift slightly inside masks.

This is how the site can feel highly animated without becoming chaotic.

# 49. Cursor Interaction Rules

Preferred approach:

- Hero visual movement
- Small card tilt

# 56. Responsive Motion Strategy

Desktop may include:

- Cursor interactions
- Magnetic buttons
- Pinned sections
- Card tilt
- Richer scroll animation

Tablet should reduce:

- Cursor-specific interactions
- Strong perspective

Mobile should simplify:

- No cursor effects
- Minimal parallax
- No fragile pinned sections
- Shorter transitions
- Vertical layouts

Mobile should still feel premium, not like a stripped-down version.

---

# 57. Accessibility Rules

The design system must support:

- Keyboard navigation
- Clear focus states
- Accessible contrast
- Semantic form labels
- Reduced motion
- Adequate tap targets
- Logical reading order
- Alt text support

Recommended minimum touch target:

```text
44 × 44px
```

Motion must never hide essential information.

---

# 58. Focus States

Every interactive element should have a visible keyboard focus state.

Preferred style:

- 2px accent outline
- Small offset
- High enough contrast

Do not remove browser outlines unless replacing them with a better accessible alternative.

---

# 59. Performance Guardrails

The website may be visually rich, but performance is still a requirement.

Rules:

- Do not animate huge background videos.
- Optimize every image.
- Lazy-load below-the-fold media.
- Avoid unnecessary JS libraries.
- Only initialize GSAP animations when needed.
- Destroy ScrollTrigger instances when appropriate.
- Avoid layout-thrashing animations.
- Keep mobile animation simpler.

---

# 60. Recommended Animation Durations

Suggested ranges:

```text
Micro hover:        150–250ms
Button transition:  200–350ms
Card interaction:   250–400ms
Section reveal:     500–900ms
Page transition:    450–700ms
Scroll sequence:    Scroll-driven
```

Avoid slow interactions that make the interface feel unresponsive.

---

# 61. Recommended Easing

Use smooth custom easing rather than default linear transitions.

Examples:

```css
cubic-bezier(0.22, 1, 0.36, 1)
cubic-bezier(0.16, 1, 0.3, 1)
```

GSAP may use similar ease profiles such as:

```text
power3.out
power4.out
expo.out
```

Use one or two primary easing styles consistently.

# 65. Design Consistency Checklist

Before approving a section, verify:

- [ ] Does it follow the brand palette?
- [ ] Is typography consistent?
- [ ] Is spacing aligned with the system?
- [ ] Does it avoid unnecessary card repetition?
- [ ] Does the layout have a clear visual hierarchy?
- [ ] Is motion purposeful?
- [ ] Does hover feel polished?
- [ ] Does it work without hover on mobile?
- [ ] Is keyboard focus visible?
- [ ] Is the section readable with reduced motion?
- [ ] Does it feel different from a generic AI template?

1. Hero reveal
2. Roles interaction
3. How It Works scroll story
4. Testimonial interaction
5. Final CTA

## Services & Pricing

Moderate motion.

Recommended major moments:

1. Service intro reveal
2. Role catalogue interactions
3. Pricing row hover
4. Referral CTA
5. FAQ

## Contact / Start Hiring

Lowest motion density.

Focus on:

- Form clarity
- Field interactions
- Progress
- Success state

The user should never struggle to complete a form because of animation.

---

# 67. Visual Rhythm Checklist

A full page should alternate between:

- Large and compact sections
- Light and dark surfaces
- Dense and spacious content
- Static and interactive moments
- Full-width and grid-based layouts

This rhythm prevents the website from feeling repetitive.

---

# 68. Mobile Design Rules

On mobile:

- Use large readable headings.
- Do not preserve desktop asymmetry if it damages readability.
- Stack content naturally.
- Keep primary CTA visible.
- Reduce animation complexity.
- Avoid horizontal scroll unless intentionally designed and clearly usable.
- Do not rely on hover.
- Ensure role rows and FAQ are touch-friendly.

# 72. Hero Technical Notes

If implementing the Kinetic Recruitment Network:

- Use DOM/SVG rather than heavy canvas if possible.
- Animate only necessary properties.
- Keep role chips accessible.
- Decorative nodes should use `aria-hidden="true"`.
- Reduce movement on mobile.
- Disable interaction when reduced motion is enabled.

---

# 73. ScrollTrigger Rules

Use ScrollTrigger only for sections where it clearly improves storytelling.

Do not attach complex ScrollTrigger timelines to every section.

Recommended major ScrollTrigger use:

- Hero entrance
- How It Works
- Selected image reveals
- Selected section transitions

---

# 74. No-JavaScript Graceful Behavior

Core content should remain visible and readable even if animation JavaScript fails.

Do not permanently hide essential content waiting for GSAP initialization.

Use progressive enhancement.

---

# 75. Design Review Questions

For every major screen, ask:

1. Does this look specifically like VActives?
2. Could this section belong to any random SaaS company?
3. Is motion supporting the message?
4. Are we repeating the same layout too often?
5. Is the content still easy to scan?
6. Is the page visually balanced?
7. Does mobile still feel intentional?
8. Is the animation smooth on average hardware?
9. Is the user always aware of the next action?
10. Would the page still work well with reduced motion?

# 76. Definition of Design Done

The design system is considered successfully implemented when:

- The approved logo and colors are used correctly.
- Typography is consistent.
- Layout follows the grid and spacing system.
- Each content type has an intentional visual treatment.
- The website does not look like a generic AI template.
- Motion is rich but controlled.
- Hover interactions are polished.
- Mobile does not depend on hover.
- Reduced-motion behavior works.
- Accessibility remains intact.
- Performance remains acceptable.
- Forms remain easy to complete.
- The visual identity feels premium, modern, international, and energetic.
